# 产品边界（决定记录）

> 写这一页的原因：2026-10 到 11 月，我们在“内核抽取 / 多宿主 / DSH 插件 / 档案 CRUD”上
> 讨论出了很多**技术上成立**的方向，但它们是**架构的整洁**，不是用户的需求。
> 这一页把边界钉死，防止（主要是我）三个月后又把复杂度捡回来。

## 一句话

**产品 = VS Code 扩展（唯一主线）。**
其它形态要么是**冻结快照**，要么是**零成本副产品**，都不再投入。

## 保留

| 东西 | 为什么留 |
|---|---|
**行动面板 + 行动账本** | 这就是产品的核心承诺：AI 在服务器上干什么，你能看见、能接手 |
**`/ui/*` 只读接口 + 账本 JSONL** | 已经写完，**零维护成本**；别人想接（DSH 浮窗、脚本、监控）随时能接，但我们不做适配层 |
**`src/core/`（M0–M2 已落地）** | 不是“为多宿主铺路”，而是**质量兜底**：core 不依赖 vscode，六道静态检查挡住装载/路径/循环类问题。0.3.14 已靠它抓出一个真 bug |
**桌面版 0.9.2 源码** | 冻结快照，只修安全/严重 bug；不再镜像功能 |

## 明确停掉

| 停掉 | 判据 |
|---|---|
**M3：SessionEngine 拆分（`terminal.ts` 瘦身）** | 它唯一的价值是“让加第二个宿主更容易”。没有第二个宿主 → 用户看不见任何变化 |
**`bastionshelld` 独立进程 + A+ 的 `owner/pid` 协调** | 同上。而且 daemon 是**产品**（自启/端口/防火墙/更新/崩溃），不是重构 |
**DSH 插件（面板 / MFA 输入 / 档案 CRUD）** | 见下节“为什么不做第二个界面” |
**档案 CRUD 的第二套 UI** | 档案是 JSONC + 系统凭据库；第二套 CRUD 必然与第一套不一致，且频率极低 |
**MFA 的跨宿主输入通道** | 低频（一次认证多会话）× 高风险（凭据过第三方/多一跳）= 不划算 |

## 为什么不做第二个界面（一条规则）

```
执行（终端）    → 必须在"人能到、能敲键盘"的宿主：VS Code / 桌面版
写配置（档案）  → 必须在"有编辑器 + 有系统凭据库"的宿主：VS Code
看（账本/状态） → 任何地方都能看：同一个 /ui（或直接读 JSONL）
```

**每个新宿主只允许加两件事：①嵌入只读视图 ②深链跳转。**
不允许加 CRUD，不允许加执行引擎，不允许复制一份语义。

## 什么情况下才重启这些被停掉的

只有**同时满足**才重启，缺一条都不算：

1. 有**真实的人**（不是我们设想的人）明确说：我不装 VS Code，但我要用 BastionShell 干活；
2. 这件事他连续两周遇到了 ≥ 5 次（不是“可能会用到”）；
3. 现有 `/ui` + JSONL 手改配置的组合**已经被他试过并且不够**。

满足 1 但没满足 2/3 → 先给文档和深链，不写代码。

## 允许的例外（已做/在做）

**多堡垒机的"厂商知识"下沉到档案**（`vendor` / `userChoice` / `assetPolicy` + 结构化提问）——
这条**是用户可感知的**（少两次交互），而且只改扩展、不加界面、不加宿主，符合上面的判据。

## 未来的默认判据

> 只做“**用户能在一次会话里感知到**”的改动。
> 看不见的改动（重构、抽象、为将来的宿主铺路）只有在**当次就能回本**时才做 ——
> 例如 M0–M2 顺手抓到了真 bug；而 M3 不会。
