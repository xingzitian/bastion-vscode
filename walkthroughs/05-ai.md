# 让 AI 也能操作服务器

扩展向 VS Code 里的 AI（Copilot Chat、Cursor、CodeBuddy 等）暴露了 8 个工具：

| 工具 | 干什么 |
|---|---|
| `bastion_listProfiles` | 列出有哪些连接档案 |
| `bastion_connect` | 连到某台机器并开会话 |
| `bastion_exec` | 在**已连接的会话**里执行命令并拿回输出 |
| `bastion_listSessions` | 看当前有哪些会话 |
| `bastion_habits` | 记住「这台机器上你习惯怎么干活」（提权方式、常用目录） |
| `bastion_tail` | 读某条会话屏幕最后几行（排障 / 人接手后确认走到哪） |
| `bastion_push` / `bastion_pull` | 传文件（没有 lrzsz 会自动降级） |

于是在聊天里可以直接说：

> 「连到生产那台，看看 nginx 为什么起不来」

AI 会自己去连、去执行、把输出读回来分析。**高危命令会被拦下来**（`rm -rf /` 之类），
不想被拦可以在 `~/.bastionshell/dangerRules.jsonc` 里改规则。

[**打开高危命令规则文件**](command:bastion.openDangerRulesFile)

## 把终端现场发给 AI

- 终端里选中文字 → `Ctrl+Alt+I` 直接送进聊天
- 没选中 → `Ctrl+Alt+Shift+I` 发最近若干行输出

[**打开日志**](command:bastion.showLog)

## 同时开多条会话（精准定位，不会串台）

同一个 AI 可以同时管多条会话：再 `connect` 一次就是**另一条独立 shell**（不同 `pid` / `tty`），
自动绑成 `A`、`B`…；也可以连接时就定名字（`bastion_connect({…, as:"db1"})`），之后 `exec` 传 `session:"A"` / `"db1"` 就只打那一条。

**两条及以上绑定时，不传 `session` 会被直接拒绝**（不会退化成"用最近活动的那条"，那样会串台）。
忘了自己在哪条？`bastion_listSessions` 里每条都标着 `你的(A)`；用完可以解绑（**解绑不关会话**）。

细节（上限 8 条别名、12 小时过期、解绑后旧别名失效等）见 README 的「一个 AI 同时管多条会话」一节。
## 长命令：别用 sleep，用 wait

构建、部署、安装这种会跑几分钟的命令，`bastion_exec` 会返回三种状态：

- `completed`：跑完了（带退出码）
- `working`：还在跑（带 `jobId`）—— **不要重发命令**，用 `bastion_wait({jobId})` 等，或 `bastion_job({jobId})` 读日志
- `input_required`：卡在密码 / 动态码 / `[y/n]` / 菜单上 —— 让用户在终端里输入

`bastion_cancel({jobId})` 可以停掉误起的命令。细节见 README「长命令：别用 sleep 硬等」。
